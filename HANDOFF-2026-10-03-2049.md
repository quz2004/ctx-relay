## Goal

When context usage passes a threshold (default 50%, range 40-60%), automatically:
write a handoff, restart with a fresh context, and read the handoff back so the work continues.

Requirements (from the user):
- Trigger only when the agent pauses and waits for the user (the **Stop** hook), never mid-run.
- Exception: at or above ~90% an emergency path may interrupt a run.
- Runs on the Claude **subscription** (OAuth login). No API key, no proxy, no `claude -p`.
- Ctrl-D, `/exit` or a crash must exit normally and never relaunch.

## Findings from the review (do not re-derive)

- `~/Downloads/Claude-plugin/context-threshold-monitor.sh` reads `context_window.remaining_pct`
  from the PreToolUse payload. That string is not in the installed Claude Code (2.1.289), so the
  hook silently no-ops. Real fields are `used_percentage`, `remaining_percentage` and
  `context_window_size`, and they appear in the **statusline** JSON, not in hook payloads.
- Hook payloads carry `transcript_path`, so usage can also be computed from the last assistant
  message's `usage` (`input + cache_read + cache_creation`) divided by the window size.
- `stop_hook_active` and `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` both exist in the binary.
- tmux `send-keys /clear` is blind typing into a TUI (half-typed input, dialogs, menu eating Enter).
  Rejected.
- LiteLLM proxy rejected: silent history rewrite instead of a real handoff, can orphan
  `tool_use`/`tool_result` pairs (HTTP 400), breaks prompt caching, fires mid-run, needs a daemon,
  and OAuth passthrough is a grey area. `claude-pro` also unsets `ANTHROPIC_BASE_URL` on purpose.
- The user's global `settings.json` has no hooks but has a Cognee statusline
  (`cognee-statusline.sh`, refreshInterval 2). The new statusline wrapper MUST call it.

## Chosen design: restart loop (no keystroke injection)

`claude-pro` stops using `exec claude` and becomes a supervisor loop:

```
rm -f "$FLAG"; claude ... & wait; rc=$?
if [[ -f "$FLAG" && fresh ]]; then rm -f "$FLAG"; relaunch with handoff prompt; else exit $rc; fi
```

Per-run state lives in `~/.claude/handoffs/<run-id>/` (`CLAUDE_PRO_RUN_ID`,
`CLAUDE_PRO_HANDOFF_DIR` exported by the wrapper): `ctx.json`, `state`, `handoff.md`, `rotate.flag`,
`claude.pid`.

Hooks and the statusline are injected with `--settings <file>` so global settings are untouched.

### State machine (Stop hook)

1. Stop, usage >= threshold, state=idle: respond
   `{"decision":"block","reason":"Write the handoff to $DIR/handoff.md ..."}`, set state=requested.
   The agent writes it in the live session (subscription, full context).
2. Next Stop, state=requested and `handoff.md` exists and is non-empty: set state=rotating, write
   `rotate.flag`, then a detached `sleep ~1s; kill -TERM <claude pid>`. The flag and the kill are
   issued together to minimize the window where a Ctrl-D could be misread as a rotation.
3. Wrapper sees the flag, relaunches: `claude --model ... "Read $DIR/handoff.md and continue from
   its Next Step. Do not re-explore."`
4. Guards: honor `stop_hook_active`; at most one block per rotation; ignore flags older than 60s;
   clear the flag before every launch; only the main-session Stop triggers (not SubagentStop).
5. Emergency (>=90%): PreToolUse hook blocks once with "write the handoff now"; the rotation then
   completes at the next Stop. Set `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` so native auto-compact does
   not win the race (verify the semantics first).

### Context reading

- Primary: statusline wrapper writes `used_percentage` + `context_window_size` to `ctx.json`, then
  delegates to the user's original statusline command.
- Fallback: Stop hook computes from `transcript_path`.
- Do not hardcode the window size (200k vs 1M).

### Handoff format

Reuse the existing `handoff` skill format: goal, state, files touched, decisions, failed attempts,
exact next step, how to verify.

## Open risks

- SIGTERM may skip SessionEnd hooks (Cognee capture). Measure; consider SIGINT or a graceful exit.
- Kill during a final render could truncate output; the ~1s delay after Stop must be validated.
- Subagent or background tasks still running at Stop: skip rotation while they exist.
- Windows is unsupported (bash + signals); document it.

## Open-source naming

Recommendation: **Baton** (a relay baton is the handoff). CLI `baton`; repo something like
`baton-for-claude-code`. Tagline: "Automatic context rollover for Claude Code: write a handoff at
the pause, restart fresh, continue where you left off."

Avoid putting "Claude" first in the project name (Anthropic trademark guidance); use
"for Claude Code" as a descriptor. Alternatives: `rollover`, `relay`, `ctx-relay`, `fresh-start`.
A quick `gh repo view` check found no exact-name clash for `baton-cc`, `claude-baton`, `ctx-baton`,
`relayloop`, but the GitHub search returned nothing, so check the name on GitHub and npm before
committing. License MIT. Ship as a plain-bash + jq launcher first; a Claude Code plugin form
(hooks via plugin) can come later, but a plugin cannot own the supervisor loop, so the
launcher stays.
